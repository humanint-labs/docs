Use [`GET /v1/providers`](/api-reference) to list provider slugs Capisum can route to. Connect credentials in the [dashboard](https://app.capisum.com) before creating transactions. See the [provider network](/guides/provider-network) for the broader integration landscape.

<Note>
  The API returns the provider **catalog**, not your connected providers. Use [`GET /v1/providers/{slug}/status`](/api-reference) or the dashboard to confirm a provider is connected and healthy.
</Note>

After you connect a provider, Capisum shows a unique incoming webhook URL for that connection (`/webhooks/{provider}/{credentialId}`). Paste that URL in the provider dashboard. PalmPay is the exception: Capisum sets `notifyUrl` on every payout automatically.

## Available providers

Seven providers are integrated and configurable in Capisum today. Refunds are not shipped for any provider. Quidax on-ramp, off-ramp, and conversion exist in code but are not on `availableOperations` yet.

| Provider | Slug | Pay-in | Payout | Balance | Account verify | Corridor notes |
| --- | --- | --- | --- | --- | --- | --- |
| Fincra | `fincra` | Yes (VA) | Yes | Yes | Yes (NGN) | NGN/GHS/KES permanent virtual accounts; NGN bank payouts; GHS/KES bank + mobile money |
| Yativo | `yativo` | Yes (VA) | Yes | — | — | Fiat VA pay-in; multi-corridor payouts (NGN, USD ACH, MXN SPEI, BRL PIX, EUR SEPA, and more) |
| Paystack | `paystack` | — | Yes | Yes | Yes (NGN) | NGN bank; GHS bank + MoMo; KES MoMo only |
| Flutterwave | `flutterwave` | — | Yes | Yes | Yes (NGN) | NGN / GHS / KES bank + mobile money |
| PalmPay | `palmpay` | — | Yes | Yes (NGN) | Yes (NGN) | NGN bank only |
| Quidax | `quidax` | Yes (crypto) | Yes | Yes | Yes (NGN) | Crypto USDT, USDC, BTC, ETH, SOL, XLM; merchant + customer wallet pay-in |
| Bitnob | `bitnob` | Yes (crypto) | Yes | Yes | Yes (NGN bank; GHS MoMo) | Fiat NGN/GHS/KES (wallet-funded); crypto payout BTC/USDT/USDC; merchant + customer-attributed pay-in |

All payout providers share the same Capisum payout state machine: queued submission, per-attempt provider transfer references, webhook matching, and verify-before-retry. Fiat virtual-account pay-in uses [Customers](/guides/pay-ins) and [pay-in destinations](/guides/pay-ins). Crypto pay-in uses the merchant/customer wallet endpoints. See [Pay-in integration](/guides/pay-ins).

### Fincra (`fincra`)

Cross-border payment infrastructure for collections, payouts, and virtual accounts across Africa. Permanent VA overview: [Fincra virtual accounts](https://docs.fincra.com/docs/fincra-virtual-accounts).

| Operation | Status |
| --- | --- |
| Payouts | Available |
| Account verification | Available (NGN) |
| Balance lookup | Available |
| Pay-in | Available (permanent VAs: NGN, GHS, KES via [`POST /v1/pay-in-destinations`](/guides/pay-ins)) |
| Refunds | Not available |

NGN destinations require `metadata.bvn`. Optional `metadata.channel` selects the issuing bank. USD/EUR/GBP FCY virtual accounts are not exposed on Capisum yet.

### Yativo (`yativo`)

Fiat virtual-account pay-in and multi-corridor payouts. Capisum manages Yativo beneficiaries and payment methods internally — you only send Capisum `destination` fields.

| Operation | Status |
| --- | --- |
| Pay-in | Available (`bank_account` destinations) |
| Payouts | Available (NGN bank transfer, USD ACH, MXN SPEI, BRL PIX, EUR SEPA, CLP/COP/PEN/ARS bank rails) |
| Balance lookup | Not available |
| Account verification | Not available |
| Refunds | Not available |

**Pay-in:** create a Capisum customer, then [`POST /v1/pay-in-destinations`](/guides/pay-ins) with `provider: "yativo"`. Supported VA currencies include BRL, MXN/MXNBASE, USD/USDBASE, and EUR/EURBASE. When KYC is outstanding, Capisum returns `verification_required` with a `verification_url`.

**Payout:** use [`GET /v1/payouts/capabilities`](/api-reference) for Yativo rails and `required_fields`. USD ACH requires a nested `destination.recipient` profile plus `routing_number` / `account_type`. See [Payout integration](/guides/payouts).

### Paystack (`paystack`)

Nigerian and African payment gateway with transfer APIs.

| Operation | Status |
| --- | --- |
| Payouts | Available |
| Account verification | Available (NGN) |
| Balance lookup | Available |
| Pay-in | Not available |
| Refunds | Not available |

Paystack reuses stored transfer recipients per organization credential to avoid duplicate beneficiary creation.

#### Disable Transfer OTP

Paystack payouts require Transfer OTP confirmation to be **disabled** on your Paystack account. This setting is Paystack-specific and applies globally, including the test environment.

1. Log in to the [Paystack Dashboard](https://dashboard.paystack.com).
2. Open **Settings** in the left menu.
3. Open the **Preferences** tab.
4. In **Transfers**, uncheck **Transfer OTP confirmation**.

### Flutterwave (`flutterwave`)

Pan-African payments platform with direct transfer APIs.

| Operation | Status |
| --- | --- |
| Payouts | Available |
| Account verification | Available (NGN) |
| Balance lookup | Available |
| Pay-in | Not available |
| Refunds | Not available |

#### Live setup

Before using Flutterwave through Capisum:

1. Connect your Flutterwave v4 credentials in the dashboard.
2. Whitelist **all** Capisum static outbound IPs in Flutterwave live settings.
3. Enable transfers on your Flutterwave account (required before payouts can work).

Full IP list and connect steps: [Flutterwave setup](/guides/flutterwave).

### PalmPay (`palmpay`)

Nigerian digital wallet and merchant payout APIs.

| Operation | Status |
| --- | --- |
| Payouts | Available (NGN bank only) |
| Account verification | Available (NGN) |
| Balance lookup | Available (NGN) |
| Pay-in | Not available |
| Refunds | Not available |

#### Live setup

Before using PalmPay through Capisum:

1. Generate an RSA key pair locally with OpenSSL and upload the public key to PalmPay.
2. Paste the matching private key into Capisum as **base64 only** (encrypted at rest; never shown again).
3. Add PalmPay’s platform public key for webhook verification.
4. Whitelist **all** Capisum static outbound IPs in PalmPay.

Full key and IP steps: [PalmPay setup](/guides/palmpay).

### Quidax (`quidax`)

Crypto deposits and withdrawals, NGN bank payouts, wallet balances, and NGN account name enquiry.

| Operation | Status |
| --- | --- |
| Payouts | Available (`bank_account` for NGN; `crypto_wallet` for USDT, USDC, BTC, ETH, SOL, XLM) |
| Account verification | Available (NGN) |
| Balance lookup | Available |
| Pay-in | Available (crypto deposit addresses) |
| On-ramp / off-ramp | Not shipped yet |
| Conversion | Not shipped yet |
| Refunds | Not available |

Crypto payouts use top-level `currency` (for example `BTC`) with `destination.type = crypto_wallet`, `destination.address`, and `destination.network`. NGN bank payouts use `destination.bank_id` from [`GET /v1/reference/banks`](/api-reference). Pay-ins have two named endpoints:

- **Merchant wallet pay-in** — [`POST /v1/transactions/pay-in/merchant-wallet`](/api-reference). Deposit address on the merchant Quidax account. Customer is optional Capisum metadata.
- **Customer wallet pay-in** — [`POST /v1/transactions/pay-in/customer-wallet`](/api-reference). Deposit address on a Quidax sub-account. Requires `customer.email`. `customer.name` is optional.

The response `deposit` object includes the address to fund and `deposit.wallet` (`merchant_wallet` or `customer_wallet`). Crypto amounts use 8 decimal minor units; NGN uses 2. Fetch wallet balances with [`GET /v1/providers/quidax/balance`](/api-reference). Verify NGN accounts with [`POST /v1/verify/account`](/guides/account-verification) and `provider: "quidax"`.

### Bitnob (`bitnob`)

Crypto-funded fiat bank payouts (wallet-funded / offchain), on-chain crypto withdrawals, and crypto pay-in addresses.

| Operation | Status |
| --- | --- |
| Payouts | Available (`bank_account` for NGN, GHS, KES; `crypto_wallet` for BTC, USDT, USDC) |
| Account verification | Available (NGN bank; GHS mobile money lookup) |
| Balance lookup | Available (defaults to the configured fiat funding wallet) |
| Pay-in | Available (BTC / USDT / USDC deposit addresses) |
| Refunds | Not available |

Pay-ins use the same Capisum endpoints as Quidax:

- **Merchant wallet** — [`POST /v1/transactions/pay-in/merchant-wallet`](/api-reference). Company Bitnob deposit address (no customer link).
- **Customer wallet** — [`POST /v1/transactions/pay-in/customer-wallet`](/api-reference). Capisum creates or reuses a Bitnob customer for `customer.email`, then generates an address with that email for attribution. Deposits still credit the company Bitnob balance — this is attribution, not an isolated sub-wallet.

Fiat payouts debit your Bitnob crypto wallet (USDT by default, or the `payoutFromAsset` you configure). Crypto payouts debit the matching asset wallet. Keep the relevant wallet funded before sending.

Set `"provider": "<slug>"` on [`POST /v1/transactions/payout`](/api-reference) to route explicitly, or omit it to use your organization's routing rules. See [Payout integration](/guides/payouts) for destination fields and examples.

**Check provider health**

```bash
curl "$CAPISUM_BASE_URL/v1/providers/paystack/status" \
  -H "Authorization: Bearer $CAPISUM_API_KEY"
```

If no health data exists yet, the response is `{ "status": "unknown" }`.

See [Account verification](/guides/account-verification) for name enquiry and balance endpoints.
