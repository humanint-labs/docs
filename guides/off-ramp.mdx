Capisum **off-ramp** converts crypto to fiat bank settlement. You call Capisum only. Capisum selects the connected provider, generates deposit instructions, tracks status, and delivers [webhooks](/guides/webhooks) when the transfer settles or fails.

Supported provider today: **OwlPay Harbor** (`provider: "harbor"`). Pass that slug (or rely on routing once configured). Do not call the provider’s APIs from your app.

```text
Create + verify customer
        ↓
Create quote → Initiate off-ramp
        ↓
Fund the returned deposit address
        ↓
Capisum webhook (settled / failed / cancelled)
```

## Endpoints

| Step | Capisum endpoint |
| --- | --- |
| Quote | [`POST /v1/offramp/quote`](/api-reference) |
| Initiate | [`POST /v1/offramp`](/api-reference) |
| Get | [`GET /v1/offramp/{id}`](/api-reference) |
| Status | [`GET /v1/offramp/{id}/status`](/api-reference) |

Quote and initiate require [`X-Idempotency-Key`](/guides/idempotency).

## Prerequisites

1. Connect an off-ramp provider in the [dashboard](https://app.capisum.com) for the environment you will use (sandbox or live).
2. Create a production or staging [API key](https://app.capisum.com/api-keys) in that same environment.
3. Create a Capisum [customer](/api-reference) and finish provider verification until Capisum reports the customer as approved. Off-ramp initiate needs that Capisum `customer_id` (`cus_…`). Provider customer IDs stay internal.

When you create the customer for off-ramp, set `provider` to the connected off-ramp slug (today `harbor`). If Capisum returns `verification_url` or `verification_status: requires_action`, complete verification before initiating.

## Amounts

All amounts are **source-asset minor units** (the crypto side of the quote).

For USDC (6 decimals):

| Amount string | Meaning |
| --- | --- |
| `10000000` | 10.000000 USDC |
| `1000000` | 1.000000 USDC |

## Successful off-ramp checklist

Complete these Capisum steps in order:

<Steps>
  <Step title="Verify the customer">
    Capisum customer exists and verification is `approved` for the off-ramp provider.
  </Step>
  <Step title="Lock a quote">
    Call quote with corridor fields while the quote is still open (`expires_at`).
  </Step>
  <Step title="Initiate">
    Pass `quote_id`, `customer_id`, sender wallet (`source.address`), and bank / beneficiary destination.
  </Step>
  <Step title="Fund the deposit">
    Send the quoted crypto amount to `instructions.address` on `instructions.network`.
  </Step>
  <Step title="Wait for settlement">
    Listen for Capisum webhooks (or poll status). Initiate alone does not mean fiat has settled.
  </Step>
</Steps>

## 1. Create a quote

Price the corridor before collecting bank details for initiate.

**Required fields (current corridors):**

| Field | Purpose |
| --- | --- |
| `source_asset` | Crypto ticker (for example `USDC`) |
| `destination_asset` | Fiat ticker (for example `USD`) |
| `amount` | Source amount in minor units |
| `network` | Chain the customer will deposit on (for example `ethereum`, `polygon`, `arbitrum`) |
| `source_country` | ISO 3166-1 alpha-2 |
| `destination_country` | ISO 3166-1 alpha-2 |

**Optional:** `provider`, `customer_type` (`individual` \| `business`), `payment_method` (for example `WIRE` when multiple rails are offered).

```bash
curl -X POST "$CAPISUM_BASE_URL/v1/offramp/quote" \
  -H "Authorization: Bearer $CAPISUM_API_KEY" \
  -H "Content-Type: application/json" \
  -H "X-Idempotency-Key: offramp-quote-001" \
  -d '{
    "provider": "harbor",
    "source_asset": "USDC",
    "destination_asset": "USD",
    "amount": "10000000",
    "network": "ethereum",
    "source_country": "US",
    "destination_country": "HK",
    "payment_method": "WIRE"
  }'
```

Save `data.id` as `quote_id`. Reusing the same idempotency key returns or refreshes that Capisum quote. Check `expires_at` before initiating.

## 2. Initiate the off-ramp

Turns an open quote into an `offramp` transaction and returns deposit instructions.

**Required for a successful initiate today:**

| Field | Purpose |
| --- | --- |
| `quote_id` | Capisum quote from step 1 |
| `customer_id` | Approved Capisum customer (`cus_…`) |
| `customer` | `email`, `first_name`, `last_name` |
| `source.address` | Wallet that will send the crypto |
| `destination` | Bank payout details for the fiat settlement |

**Destination fields commonly required:**

- `type`: `bank_account`
- `bank_name`, `account_holder_name`, `account_number`
- `swift_code` and/or `routing_number` / `iban` as the corridor requires
- `transfer_purpose` (for example `SALARY`)
- `is_self_transfer` when applicable
- `beneficiary` — name, `dob` (`YYYY-MM-DD`), `id_doc_number`, and `address` (`street`, `city`, `country`, plus optional `state_province` / `postal_code`)

Exact corridor requirements are enforced by Capisum at initiate time; missing fields return a validation or provider error.

```bash
curl -X POST "$CAPISUM_BASE_URL/v1/offramp" \
  -H "Authorization: Bearer $CAPISUM_API_KEY" \
  -H "Content-Type: application/json" \
  -H "X-Idempotency-Key: offramp-tx-001" \
  -d '{
    "quote_id": "QUOTE_UUID",
    "provider": "harbor",
    "customer_id": "cus_…",
    "customer": {
      "email": "customer@example.com",
      "first_name": "Test",
      "last_name": "User"
    },
    "source": {
      "address": "0x4B20993Bc481177ec7E8f571ceCaE8A9e22C02db"
    },
    "destination": {
      "type": "bank_account",
      "bank_name": "The Hongkong and Shanghai Banking Corporation Limited",
      "account_holder_name": "CHAN TAI MAN",
      "account_number": "123456789012",
      "swift_code": "HSBCHKHH",
      "transfer_purpose": "SALARY",
      "is_self_transfer": true,
      "beneficiary": {
        "name": "CHAN TAI MAN",
        "dob": "1990-01-01",
        "id_doc_number": "12345678",
        "address": {
          "street": "xxx 1234th Ave S",
          "city": "Minneapolis",
          "state_province": "MN",
          "postal_code": "55416",
          "country": "US"
        }
      }
    }
  }'
```

On success Capisum returns a transaction with `status: processing` and `instructions` for the crypto deposit:

| Field | Meaning |
| --- | --- |
| `instructions.type` | `crypto_deposit` |
| `instructions.address` | Address to fund |
| `instructions.network` | Network to use |
| `instructions.amount_expected` | Amount Capisum expects (when provided) |
| `instructions.next_step` | Typically `await_crypto_deposit` |

Save `id` / `reference` for status and webhook matching. Capisum does not expose provider transfer IDs on the public response.

## 3. Fund the deposit and settle

1. Instruct the end user to send the quoted crypto amount to `instructions.address` on `instructions.network`.
2. Keep the Capisum transaction in `processing` until settlement.
3. Prefer [outgoing webhooks](/guides/webhooks); optionally poll [`GET /v1/offramp/{id}/status`](/api-reference).

| Capisum event | When |
| --- | --- |
| `transaction.settled` | Off-ramp reaches `completed` / `settled` — fiat path finished |
| `transaction.failed` | Off-ramp reaches `failed` |
| `transaction.cancelled` | Off-ramp reaches `cancelled` (expired or cancelled) |

Quote creation and initiate do **not** emit these events. Funding and provider settlement drive them.
